# MOHIT.OS Asset Manifest

Artwork is generated by `scripts/mohit_os.py` from curated project/skill data and the GitHub contribution calendar.

| Asset | Purpose |
|---|---|
| assets/boot/boot-sequence.gif + boot-static.png | Wide terminal boot and static fallback |
| assets/identity/biometric-scan.svg | Operator identity scan |
| assets/world/project-universe.svg | Categorized project universe |
| assets/profile/skill-matrix.svg | Technology inventory |
| assets/living-machine/neural-network.gif + neural-network-static.png | Contribution-driven neural visualization and fallback |
| assets/telemetry/dashboard.svg | Public GitHub metrics |
| assets/telemetry/languages.svg | Public repository language distribution |
| assets/achievements/achievement-board.svg | Verified contribution milestones |
| assets/shutdown/system-shutdown.svg | Closing terminal panel |

## Data
- `data/projects.json`: curated public projects and verified links.
- `data/skills.json`: technology inventory; no invented proficiency values.
- `data/profile.json`: generated public GitHub metrics.
- `assets/activity/contributions.json`: contribution calendar from GitHub GraphQL.

## Local build
`python -m pip install -r requirements.txt`
`GITHUB_TOKEN=YOUR_TOKEN python scripts/update_profile_metrics.py`
`python scripts/mohit_os.py --render --validate`

## Automation safety
Pull-request builds commit generated artwork only to the pull request's head branch. Scheduled refreshes create a separate automation branch and open a PR to `main`. No workflow pushes generated commits directly to `main`, and no workflow merges a PR.

Legacy art directories are retained for now as source/history; the new README does not reference them.
